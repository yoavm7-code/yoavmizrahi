## Chosen approach

### Data

- `content/site.json` is the single source of truth: `schemaVersion`, `site` (name, title, description, email, links, tagline), `desk` (note text, objects with `id`, `style`, `x`, `y`, `r`, `mobileOrder`), `works[]`, `films[]`, `about`.
- Every item has a stable `id`. Media paths point into `media/`.

### Rendering

- One shared module `js/render.js` builds every page from the data. It inserts text with `textContent` / `createElement` only, never `innerHTML` with content.
- The admin runs `render.js` in the browser and commits the finished `index.html`. Visitors get complete HTML: no blank flash, readable by search engines and link previews. No build step: the admin is the builder.
- Generated files carry a "generated by the admin" comment and a `data-build` marker.
- The site stays a single page with hash routes, so the wipe and transitions are untouched. Each work and film also gets a small share page (`/w/<id>/`) with its own title and preview card that sends visitors into the site.
- `js/main.js` keeps attaching behavior (drag, wipe, split headings, demos, reel) to the markup.

### Admin (`/admin/`)

- A separate page, unlinked, `noindex`. Loads no outside scripts. Imports only `render.js` from the site.
- Sections: Desk, Works, Films, About, Site settings, History.
- Live preview of the real site fed by the draft.
- Arrange mode: the preview loads the real site with an arrange flag, reuses the existing desk drag code, and sends positions back. Phone stack order is a drag-handle list.
- Drafts autosave locally and sync to the `drafts` branch.
- Publish: validate the data, dry-run render, refuse on any error, then one atomic commit (JSON + HTML + media) through the Git Trees API. Base-SHA check; on mismatch, re-fetch and explain in plain words. Then poll the live site with a cache-busting query until the new `data-build` shows, and show "Live".
- History in plain words ("Tue 14:02, added Ad Intel") with one-click restore (a new commit that restores a past state).
- `/admin/rescue.html`: a single file with one-tap "undo last publish" that works even if the admin breaks.
- Guided key setup with screenshots, expiry date shown, "get a new key" flow.
- Installable to the phone home screen.

### Media

- Images re-encoded in the browser through a canvas (strips EXIF and GPS), long edge capped at 2400px, named by content hash, kept small.
- Short screen recordings allowed with a size cap. Films stay on YouTube (video id).
- Media is never deleted on publish, so restoring any version shows the right images.

### Mobile

- Under 720px the desk becomes a stack ordered by `mobileOrder`.
- Films timeline fits the phone width.
- Project pages, menu and About tuned for phone.
- 44px touch targets, `100dvh`, sensible `touch-action`, camera-friendly file picker in the admin.

## Security

- **Sensitive data:** the GitHub key. Nothing else is private (the repo is public, drafts included, by decision).
- **Key scope:** fine-grained token, only this repo, Contents read/write only, with an expiry.
- **Key storage:** in the open tab only on `*.github.io`. On the custom domain, optional "keep me signed in" (localStorage). Never logged, never shown after entry, only ever sent to api.github.com.
- **Attack surface:** the admin page is public but useless without the key. A strict meta CSP, no third-party scripts, all content rendered as text, and the admin refuses to run inside a frame.
- **Shared origin:** on `yoavm7-code.github.io` every Pages repo of the account shares the origin. The custom domain removes this. Until then, the protections above apply.
- **Validation:** everything is checked against the schema in the admin before publish; the render refuses bad data. URLs are allowed only for http/https/mailto. YouTube ids are checked against the id pattern.
- **Fail safe:** publish is atomic. History is append-only (restores are new commits). A rescue page undoes the last publish independently of the admin.
- **Privacy:** photo location data is stripped on upload.
- **Logging:** none. The admin never sends the key or content anywhere except api.github.com.

## Alternatives rejected

- **Local-only admin:** can't edit from a phone.
- **Ready-made git CMS (Sveltia, Decap):** generic look, no live desk preview, Decap needs an outside login service.
- **Rendering the site from JSON at runtime:** blank flash on first paint, worse for search and link previews.
- **A separate page per route:** would mean rewriting the router the wipe depends on. Share pages give the same link previews with no risk.
- **Rebuilding the desk inside the admin:** the real site's drag code already does it, and what you see is exactly what visitors get.
